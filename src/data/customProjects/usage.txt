================================================================================
  CUSTOM PROJECTS — USAGE GUIDE
  (This file is for reference only and will NEVER create a node.)
================================================================================

1. HOW TO ADD A NEW CUSTOM PROJECT NODE
--------------------------------------------------------------------------------
Inside `src/data/customProjects/`, create a new folder named whatever you want
the project to be called, then add a `project.json` file inside it.

Example folder structure:

  src/data/customProjects/
  ├── usage.txt                   <-- This guide (ignored by the loader)
  ├── AntiCEL/
  │   ├── project.json            <-- Project metadata
  │   └── screenshots/            <-- Optional local photos folder
  │       ├── 01-garage.png
  │       └── 02-3d-history.png
  └── My New Project/
      ├── project.json
      └── screenshots/            <-- Optional! Omit if no photos yet
          └── 01-home.png

The folder name automatically becomes the project's title (unless you override
it with a `"title"` field inside `project.json`). As soon as you add the folder
and `project.json`, the node appears automatically — no code edits needed!


2. MANDATORY FIELDS IN `project.json`
--------------------------------------------------------------------------------
Every `project.json` must include these 4 fields:

  - "shortDescription" (string)
      1–2 sentence overview displayed in the 1st-click half-opened card.

  - "date" (ISO date string, e.g. "2026-11-19" or "2026-11-19T00:00:00Z")
      Determines which Year Ring the node sits in AND its radial distance
      within that year based on month/day.

  - "categories" (array of strings)
      Classifies the project for the top category switcher.
      Allowed values:
        "Web App"
        "AI/ML"
        "Cybersecurity"
        "Software/Hardware"
        "Mobile Dev"
        "Video Game Dev"
        "Systems & Tools"
        "Cloud & DevOps"
        "Data Science"
      (Categories with 0 tagged projects stay automatically hidden until used.)

  - "techStack" (array of strings)
      Technologies shown as badges in the overview card and full catalog
      (e.g. ["Swift", "SwiftUI", "WidgetKit"]).


3. OPTIONAL FIELDS IN `project.json`
--------------------------------------------------------------------------------
  - "title" (string)
      Overrides the folder name as the displayed title.

  - "fullSummary" (string)
      Longer description shown in the 2nd-click Full Catalog view.
      (Defaults to `shortDescription` if omitted.)

  - "highlights" (array of strings)
      Bullet points shown under "Key Highlights" in the Full Catalog view.

  - "displayDate" (string, e.g. "Nov 2026")
      Custom formatted date label. (Auto-formatted from `date` if omitted.)

  - "liveUrl" (string)
      External link (live website, demo, or App Store link).
      Note: Any `apps.apple.com` link is automatically labeled "App Store".

  - "githubUrl" (string)
      Link to a public GitHub repo if applicable. Omit for private repos.

  - "isPrivate" (boolean, default: false)
      Set to `true` to show the amber "Private Repo" badge.

  - "featured" (boolean, default: false)
      Marks the project as featured.

  - "hidden" (boolean, default: false)
      Set to `true` to temporarily hide this project node without deleting it.

  - "images" (array of { "src": "...", "alt": "...", "caption": "..." })
      Optional external image URLs (such as App Store CDN URLs).


4. HOW SCREENSHOTS / PHOTOS WORK
--------------------------------------------------------------------------------
Option A — Local `screenshots/` folder (Recommended):
  1. Create a `screenshots` folder inside your project folder:
       src/data/customProjects/<Project Name>/screenshots/
  2. Drop any image files inside it:
       Supported formats: .png, .jpg, .jpeg, .webp, .gif, .avif
  3. Number filenames to control their exact order in the gallery:
       01-home-screen.png
       02-dashboard.jpg
       03-settings.webp
  4. Filenames are automatically turned into clean captions (leading numbers,
     dashes, and underscores are stripped, e.g. `01-home-screen.png` ->
     `Home Screen`).
  5. Vite automatically bundles and rewrites the image paths for GitHub Pages
     (`/Portfolio/`), so you never need to configure paths manually.

Option B — External URLs in `project.json`:
  Add an `"images"` array in `project.json` with full `https://...` URLs.
  If a project has BOTH local `screenshots/` files AND `"images"` URLs,
  local screenshots appear first, followed by the external URLs.

If a project has no screenshots yet, the Full Catalog view automatically
displays a sleek neural schematic blueprint card as a placeholder.


5. MINIMAL COPY-PASTE TEMPLATE (`project.json`)
--------------------------------------------------------------------------------
{
  "shortDescription": "Concise 1-2 sentence overview for the 1st-click card.",
  "fullSummary": "Detailed write-up of what the project does, architecture, and impact.",
  "highlights": [
    "Key technical achievement or feature #1",
    "Key technical achievement or feature #2"
  ],
  "date": "2026-11-19",
  "categories": ["Web App", "Systems & Tools"],
  "techStack": ["TypeScript", "React"],
  "liveUrl": "https://example.com",
  "isPrivate": true
}


6. PUBLIC GITHUB REPOS & HIDING REPOS
--------------------------------------------------------------------------------
- Public repositories on your GitHub account are pulled automatically.
- To assign categories, custom summaries, highlights, or hide a public GitHub
  repo, edit `PROJECT_OVERRIDES` or `HIDDEN_REPOS` in:
    src/data/portfolioConfig.ts

When finished, commit & push to `main` — GitHub Actions automatically rebuilds
and publishes your updated portfolio to GitHub Pages.
